# WTQ-Bill-AI-Assitant

Reads electricity bill images (K-Electric, LESCO, IESCO).

- **Level 1** writes one 18-key JSON object per bill into `level1.csv`.
- **Level 2** answers 12 customer questions per bill in plain English into `level2.csv`.
- **Streamlit app** (`app.py`) lets you upload a bill, see the decoded details, and ask guarded free-text questions.

## Submission layout

```text
output/level1.csv     10 rows: bill_id, json
output/level2.csv     120 rows: bill_id, question_id, question, answer
source/               this project (README.md, .env.example, requirements.txt, bill_decoder/, app.py, tests/)
demo/demo.mp4         optional demo video
```

Both CSV files are generated by the code below from the supplied templates; nothing is edited by hand.

## How it works

### Level 1
1. Load the image (Pillow, EXIF orientation applied).
2. OCR with RapidOCR (local) into positioned text lines.
3. Detect the provider from OCR keywords, cross-checked against the file-name prefix. LESCO bills are also classified as `standard`, `web` or `digital` layout, each with its own prompt.
4. One Gemini call per bill (image + OCR text + provider prompt, JSON mode, temperature 0, fixed seed). The model only copies printed strings and never does arithmetic. It also copies the consumption history (`bill_history`).
5. Code turns the strings into numbers and dates, applies signs, sums meter rows, picks the highest late-payment amount, and uses the bill's own arithmetic to match shifted values to labels on LESCO/IESCO photos.
6. Hard checks (schema, enums, parseable amounts) trigger up to 2 retries with the error fed back. Arithmetic mismatches are only logged to `work/<bill_id>/warnings.txt`.
7. The `json` column of the supplied template is filled in order via Python's `csv` module.

A bill that fails still gets a complete 18-key row and the run continues.

### Level 2
1. Level 1 artifacts are loaded (or produced) per bill.
2. `factsheet.py` computes every number the questions need (shares, penalties, history statistics, estimates). Each metric is `{"value", "reason"}`.
3. One Gemini call per bill answers all 12 questions. The model sees the fact sheet, the raw extraction and the image, and may call a `calculate` tool (safe AST arithmetic in `calc.py`) for anything not in the fact sheet. It never does arithmetic itself.
4. Hard checks (missing/duplicate IDs, empty text, leaks, URLs, length) retry only the failing question IDs (max 2). Failures fall back to a fixed sentence so no cell is ever empty. Soft checks (numbers not traceable to the fact sheet or tool results) are logged to `work/<bill_id>/l2_warnings.txt`.

### Determinism and guardrails
- Temperature 0 and a fixed seed, plus a **content-addressed answer cache** (`work/<bill_id>/answer_cache.json`). The key is model + prompt version + normalised question + hash of the bill evidence, so asking the same question twice returns the identical text without a model call.
- Free-text questions (UI) pass a strict, deterministic allow-list guard first: only questions about the bill, its charges, usage and payment are answered. Prompt-injection attempts, requests for personal identifiers or other topics get a fixed refusal and never reach the model.
- Untrusted question text is delimited and the model is told never to obey it. Only the `calculate` tool is exposed and it cannot run code. Answers are rejected if they contain URLs, identifier leaks, system-prompt echoes or are too long.
- Personal identifiers (names, addresses, CNIC, account/reference/consumer/meter numbers) are never output.

## Runtime

Python 3.12.

## Setup

```bash
cd source
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # Windows: copy .env.example .env
# edit .env and set API_KEY
```

## Run

Run from the `source/` folder.

```bash
# both levels (writes output/level1.csv and output/level2.csv, prints a per-bill summary)
python -m bill_decoder.run_all --bills ../test/bills --csv-dir ../test/csv --out ../output --work ../work

# Level 1 only
python -m bill_decoder.level1 --bills ../test/bills --template ../test/csv/level1.csv --out ../output/level1.csv --work ../work

# Level 2 only
python -m bill_decoder.level2 --bills ../test/bills --template ../test/csv/level2.csv --out ../output/level2.csv --work ../work

# web UI
streamlit run app.py
```

Add `--reuse-raw` (Level 1) to rebuild from saved `raw.json` without API calls; add `--force` (Level 2 / run_all) to ignore cached results and re-ask the model.

## Tests

```bash
python -m pytest tests -q
python tests/score_level1.py --csv ../output/level1.csv   # compare with hand-checked training bills
```

`tests/expected/` holds expected JSON for the five training bills (KESC_0008 equals the guide). `tests/raw/` holds raw extractions used to test assembly without an API.

## Decisions on ambiguous cases

- KE `units_consumed`: the printed "N units =" headline when present, otherwise the sum of the meter rows.
- Meter tables with several rows: readings are column sums (a single row is used as printed). Unreadable cells make a sum `null`.
- IESCO "Total FPA" is a charge (`fpa`); `total_charges` stays the printed subtotal.
- `payable_after_due_date` is `null` when only text such as "NOT TO BE PAID" is printed.
- History for non-KE bills contains previous months only; the current month is added from Level 1.

## AI usage

- **Models / APIs used by the code:** Gemini 3.1 Flash-Lite (`gemini-3.1-flash-lite`, the default in `.env.example` and `config.py`) through the Google AI Studio API (`google-genai` SDK), for Level 1 extraction and Level 2 answer wording. `gemini-3.5-flash-lite` also works by changing `MODEL_NAME`; the submitted `output/*.csv` files were generated with `gemini-3.5-flash-lite`.
- **Local services:** RapidOCR (`rapidocr-onnxruntime`) for OCR. All arithmetic is done by code.
- **AI tools used to write the code:** Claude and Cursor (AI coding assistants).
- **Other:** none.
